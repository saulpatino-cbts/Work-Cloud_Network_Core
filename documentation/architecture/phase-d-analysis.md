# Phase D — AI Analysis Engine Architecture

> Version: 1.0.0 | Status: ACTIVE | Date: 2026-03-05

---

## What Phase D Delivers

Phase D consumes the `AWSTopology` and `AzureTopology` checkpoints written by
Phase C and produces a versioned `FindingsReport` written to `EngagementStore`.
Every finding is fact-based, severity-rated, framework-mapped, and deduplicated.
Phase E (Report Generation) consumes the `FindingsReport` — it never reads
topology directly.

---

## Data Flow

```
EngagementStore (Phase C output)
  aws_{account}_{region}.json   ─┐
  azure_{sub_id}.json           ─┤
                                  ▼
                         AnalysisEngine.run()
                          │
                          ├─ _analyze_aws_region()      ─── 11 AWS finding rules
                          ├─ _analyze_azure_subscription() ─ 7 Azure finding rules
                          ├─ ObservedStateEnforcer        ── blocks hedge language
                          ├─ Deduplication register        ── {rule_id}:{resource_id}
                          └─ EscalationEngine              ── CRITICAL alert (DD-016)
                                  │
                                  ▼
                         FindingsReport (review_complete=False)
                                  │
                                  ▼
                         RecommendationEngine.enrich()
                          │
                          ├─ MCPRouter ──► AWSMCPClient  (awslabs/mcp)
                          │           └─► AzureMCPClient (Azure/azure-mcp)
                          └─ Offline fallback library   (if MCP unavailable)
                                  │
                                  ▼
                         FindingsReport (enriched, review_complete=False)
                                  │
                                  ▼
                         EngagementStore.write_findings_report()
                         engagements/{id}/findings/report.json
```

---

## Design Contracts (All Enforced in Code)

| Contract | Where Enforced | What Happens on Violation |
|---|---|---|
| DD-002: `observed_state.fact` must not contain hedge language | `ObservedStateEnforcer.validate()` called in `_emit()` | `ObservedStateViolation` raised — finding never reaches report |
| DD-002: `framework_mappings` must not be empty | `_emit()` validation | `ValueError` raised — finding never reaches report |
| DD-003: Findings and recommendations are generated by separate code paths | `AnalysisEngine` has no recommendation logic; `RecommendationEngine` has no finding logic | Structural separation — no shared state |
| DD-008: Engine reads from store only — never touches client environment | `AnalysisEngine.__init__` takes `EngagementStore` as only data source | No cloud SDK calls in analysis engine |
| DD-009: `review_complete=False` on all generated reports | `FindingsReport` hardcoded `review_complete=False` in `run()` | Report engine (Phase E) raises `ReviewGateError` until set to True |
| DD-016: CRITICAL findings trigger escalation | `EscalationEngine.process()` called after finding collection | Escalation logged with finding list before report is written |

## MCP Integration

The recommendation engine connects to two MCP servers:

| Server | Repo | Transport | Tool Used |
|---|---|---|---|
| AWS MCP Server | `awslabs/mcp` | stdio (local subprocess) | `aws.well-architected.get-recommendation` |
| Azure MCP Server | `Azure/azure-mcp` | SSE | `azure.advisor.get-recommendation` |

Both clients degrade gracefully: if the `mcp` package is not installed or the
server is unreachable, `RecommendationEngine` applies the offline fallback library.
Findings are never blocked waiting for MCP responses.

MCP is configured via:
```bash
CNA_AWS_MCP_ENDPOINT=...    # default: empty (local stdio)
CNA_AWS_MCP_TRANSPORT=stdio # default: stdio
CNA_AZURE_MCP_ENDPOINT=...  # default: empty
CNA_AZURE_MCP_TRANSPORT=sse # default: sse
```

## Review Gate (DD-009)

The `FindingsReport` is always written with `review_complete=False`.
Phase E's report engine raises `ReviewGateError` if it reads a report where
`review_complete` is still `False`.

To mark a report reviewed:
```bash
cna review complete --engagement-id acme-20260305-a3f2
# Sets review_complete=True in findings/report.json
# Records reviewer name and timestamp in audit log
```

## CLI Usage

```bash
# Full analysis (AWS + Azure)
cna analyze \
  --engagement-id acme-20260305-a3f2 \
  --aws --azure

# AWS only, dry run (findings generated, not written)
cna analyze \
  --engagement-id acme-20260305-a3f2 \
  --aws --dry-run

# Offline / air-gapped (skip MCP enrichment)
cna analyze \
  --engagement-id acme-20260305-a3f2 \
  --aws --azure --no-recommendations
```
